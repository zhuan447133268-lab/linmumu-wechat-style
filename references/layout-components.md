# 林木木风格公众号排版组件库

> 源头：Obsidian 排版四件套（Skill-林木木公众号排版 / Prompt-公众号排版Agent / 5段式叙事组件映射 / 林木木风格公众号组件库方案），本文件已合并去重。

## 一、3 条视觉铁律

| 维度 | 规则 | 为什么 |
|---|---|---|
| **语气** | 口语化 + 自嘲人设 | 降低阅读门槛，拉近距离 |
| **节奏** | 短段落、多用 emoji、隔几句就来个视觉块 | 公众号手机屏阅读，必须透气 |
| **情绪曲线** | 痛点→发现→效果→对比→自嘲收尾 | 验证过的叙事结构，不要改 |

> 所有组件围绕这三条设计，不为好看加花哨效果。

## 二、叙事段 → 组件映射速查表

| 叙事段 | 组件名 | 核心 emoji | 作用 |
|---|---|---|---|
| 1. 痛点故事 | **痛点钩子框** | 😩 / 🤯 | 用具体场景把读者拽进来 |
| 2. 发现转折 | **顿悟金句卡** | 💡 | "后来我才发现……"式转折 |
| 3. 效果展示 | **前后对比栏** | ❌ / ✅ | 直观展示变化/收益 |
| 4. 对比分析 | **正反对比表** | 🟢 | 老办法 vs 新办法 |
| 5. 自嘲收尾 | **小林收尾框** | 🙈 / 🫠 | 自嘲 + 引导互动 |

补充组件（观点文）：恶评/引用句 → 💬 灰色气泡（像弹幕）；全文核心句 → 绿底高亮框；两栏/三栏对比 → 表格布局（不用 flex，公众号编辑器粘贴最稳）。

## 三、5 个核心组件详规

### 组件 1：痛点钩子框

**使用时机**：文章开头 100 字内
**视觉规范**：浅灰底 + 左边 4px 橙色竖条；开头 😩 或 🤯；第一人称口语短句

**文案模板**：

```
😩 说实话，我以前也以为 [某个普遍误区]。
直到 [某个具体场景] 发生了，我才反应过来——
原来 [真正的痛点]。
```

**示例**：

> 😩 说实话，我以前写公众号也是写完就丢，排版全凭感觉。
> 直到有次领导截图问我："你这段和上面是不是同一个人写的？"我才反应过来——原来风格不统一，读者也会懵。

### 组件 2：顿悟金句卡

**使用时机**：痛点讲完后，转折到发现
**视觉规范**：白色卡片 + 浅绿阴影；顶部 💡；核心金句加粗、放大一号

**文案模板**：

```
💡 后来我才发现：
[一个反直觉的结论]

不是 [表象原因]，而是 [本质原因]。
```

**示例**：

> 💡 后来我才发现：
> **排版不是审美问题，是效率问题。**
> 不是我不会设计，而是我每次都在重复造轮子。

### 组件 3：前后对比栏

**使用时机**：讲完发现后，展示效果
**视觉规范**：左右两栏：左 ❌ 以前（灰底），右 ✅ 现在（绿底）

**文案模板**：

```
❌ 以前                    ✅ 现在
[老状态1]                 [新状态1]
[老状态2]                 [新状态2]
```

**示例**：

> ❌ 以前：写完文章排版 2 小时，风格还不一样
> ✅ 现在：Agent 30 秒出稿，视觉统一

### 组件 4：正反对比表

**使用时机**：讲清楚"为什么这个方法更好"
**视觉规范**：3 列表格：维度 / 传统做法 / 林木木做法；表头深绿底白字；关键差异标 🟢

**文案模板**：

```
| 维度 | 传统做法 | 林木木做法 |
|---|---|---|
| 排版 | 手动调格式 | Agent 自动套用组件 |
| 风格 | 每篇像不同人写的 | 固定视觉铁律 |
| 时间 | 2 小时 | 5 分钟 |
```

### 组件 5：小林收尾框

**使用时机**：文章最后，自嘲 + 互动
**视觉规范**：圆角虚线框；开头 🙈 或 🫠；文字俏皮，结尾抛问题

**文案模板**：

```
🙈 好了，我又在这儿叨逼叨了半天。
其实我也就是个 [自嘲身份]，
[一句真诚的总结]。

你 [抛一个问题给读者]？评论区聊聊，我每条都看。
```

**示例**：

> 🙈 好了，我又在这儿叨逼叨了半天。
> 其实我也就是个被排版折磨过的普通运营。
> 如果你也讨厌每次手动调格式，这套组件库你值得一试。
> 你写公众号最烦哪一步？评论区聊聊，我每条都看。

## 四、排版 Agent Prompt（复制即用）

```markdown
你是一位公众号排版助手，专门帮我用"林木木风格组件库"排版文章。

我的写作风格是：
- 口语化 + 自嘲人设
- 叙事结构：痛点故事 → 发现 → 效果 → 对比 → 自嘲收尾
- 整体语气生动调皮，不要太正经

排版规则：
1. 读完我的文章后，自动识别每一段属于哪个叙事段
2. 按以下映射套用组件：
   - 痛点故事 → 痛点钩子框
   - 发现转折 → 顿悟金句卡
   - 效果展示 → 前后对比栏
   - 对比分析 → 正反对比表
   - 自嘲收尾 → 小林收尾框
3. 每个组件必须包含对应的 emoji
4. 段落要短，手机屏阅读友好
5. 不要改动我的原文意思，只做排版增强

请输出排版后的完整公众号文章（HTML/Markdown 均可）。
```

精简版：

```markdown
用林木木风格组件库排版这篇文章：
5段叙事（痛点→发现→效果→对比→自嘲），口语化自嘲语气，多用 emoji，段落要短。
```

## 五、成功标准

- [ ] 新文章从写完正文到排版完成 ≤ 10 分钟
- [ ] 连续 3 篇文章视觉风格一致
- [ ] 读者评论里出现"你的排版好认"或类似反馈
- [ ] 自己写文章时不再为排版分心
