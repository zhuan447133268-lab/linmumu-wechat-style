# 林木木风格公众号组件库 · 内容操作系统组件层

> 源头：Obsidian 排版四件套（Skill-林木木公众号排版 / Prompt-公众号排版Agent / 5段式叙事组件映射 / 林木木风格公众号组件库方案），本文件已合并去重并升级为内容操作系统组件层。

## 一、3 条视觉铁律

| 维度 | 规则 | 为什么 |
|---|---|---|
| **语气** | 口语化 + 自嘲人设 | 降低阅读门槛，拉近距离 |
| **节奏** | 短段落、空行制造呼吸感、视觉块只在情绪转折点出现 | 公众号手机屏阅读，必须透气 |
| **情绪曲线** | 按文章类型走结构，不要所有文章套同一个模板 | 工具实践、观点、成长复盘各有自己的路 |
| **emoji** | 作为**情绪锚点**使用，不是排版装饰；每个组件只用一个核心 emoji，全文不重复堆砌 | 避免模板味，保持"像人说话" |

> 所有组件围绕这四条设计，不为好看加花哨效果。

## 二、文章类型 → 结构 → 组件路由

Agent 排版前必须先判断文章类型，再选结构和组件。

| 文章类型 | 核心结构 | 常用组件 |
|---|---|---|
| **工具实践文** | 痛点 → 踩坑 → 发现 → 效果 → 方法论 | 痛点钩子框、踩坑复盘卡、顿悟金句卡、前后对比栏、收尾框 |
| **观点文** | 钩子 → 事件 → 反转 → 自我审判 → 升维 → 收口 | 痛点钩子框/现象钩子、顿悟金句卡、引用句气泡、收尾框（留白版） |
| **成长复盘文** | 过去我 → 转折 → 行动 → 新认知 | 踩坑复盘卡、顿悟金句卡、时间线/步骤表、收尾框（自嘲版） |

## 三、叙事段 → 组件映射速查表

| 叙事段 | 组件名 | 核心 emoji | 作用 |
|---|---|---|---|
| 痛点故事 | **痛点钩子框** | 😩 / 🤯 | 用具体场景把读者拽进来 |
| 踩坑复盘 | **踩坑复盘卡** | 🫠 | 暴露错误判断 → 真实情况 → 经验 |
| 发现转折 | **顿悟金句卡** | 💡 | "后来我才发现……"式转折 |
| 效果展示 | **前后对比栏** | ❌ / ✅ | 直观展示变化/收益 |
| 对比分析 | **正反对比表** | 🟢 | 老办法 vs 新办法 |
| 自嘲/互动收尾 | **收尾框** | 🙈 / 🫠 / — | 自嘲、留白或引导互动 |

补充组件（观点文）：恶评/引用句 → 💬 灰色气泡（像弹幕）；全文核心句 → 绿底高亮框；两栏/三栏对比 → 表格布局（不用 flex，公众号编辑器粘贴最稳）。

## 四、6 个核心组件详规

### 组件 1：痛点钩子框

**使用时机**：文章开头 100 字内
**视觉规范**：浅灰底 + 左边 4px 橙色竖条；开头 😩 或 🤯；第一人称口语短句

**文案模板**：

```markdown
😩 说实话，我以前也以为 [某个普遍误区]。
直到 [某个具体场景] 发生了，我才反应过来——
原来 [真正的痛点]。
```

**示例**：

> 😩 说实话，我以前写公众号也是写完就丢，排版全凭感觉。
> 直到有次领导截图问我："你这段和上面是不是同一个人写的？"我才反应过来——原来风格不统一，读者也会懵。

---

### 组件 2：踩坑复盘卡

**使用时机**：工具实践文或成长复盘文中，暴露真实错误判断并带出经验
**视觉规范**：浅灰底 + 左边 4px 红色竖条；顶部 🫠；分三段："一开始我以为" / "后来发现" / "这件事告诉我"

**文案模板**：

```markdown
🫠 我踩的坑

一开始我以为：
[错误判断]

后来发现：
[真实情况]

这件事告诉我：
[可迁移的经验，落在具体小动作]
```

**示例**：

> 🫠 我踩的坑
>
> 一开始我以为：
> 中文包报错是字体没装对，换个字体就能解决。
>
> 后来发现：
> 是渲染器把中文字符当成了占位符，根本和字体无关。
>
> 这件事告诉我：
> 遇到中文显示问题，先查编码再查字体，顺序错了会白折腾两小时。

---

### 组件 3：顿悟金句卡

**使用时机**：痛点/踩坑讲完后，转折到发现
**视觉规范**：白色卡片 + 浅绿阴影；顶部 💡；核心金句加粗、放大一号

**文案模板**：

```markdown
💡 后来我才发现：
[一个反直觉的结论]

不是 [表象原因]，而是 [本质原因]。
```

**示例**：

> 💡 后来我才发现：
> **排版不是审美问题，是效率问题。**
> 不是我不会设计，而是我每次都在重复造轮子。

**金句卡使用门槛**：必须满足以下三点，否则不要用这个组件：
1. 能脱离上下文独立阅读
2. 有观点变化（不是同义反复）
3. 有记忆点（读者愿意截图或转发）

---

### 组件 4：前后对比栏

**使用时机**：讲完发现/踩坑后，展示效果
**视觉规范**：左右两栏：左 ❌ 以前（灰底），右 ✅ 现在（绿底）

**文案模板**：

```markdown
❌ 以前                    ✅ 现在
[老状态1]                 [新状态1]
[老状态2]                 [新状态2]
```

**示例**：

> ❌ 以前：写完文章排版 2 小时，风格还不一样
> ✅ 现在：Agent 30 秒出稿，视觉统一

---

### 组件 5：正反对比表

**使用时机**：讲清楚"为什么这个方法更好"
**视觉规范**：3 列表格：维度 / 传统做法 / 林木木做法；表头深绿底白字；关键差异标 🟢

**文案模板**：

```markdown
| 维度 | 传统做法 | 林木木做法 |
|---|---|---|
| 排版 | 手动调格式 | Agent 自动套用组件 |
| 风格 | 每篇像不同人写的 | 固定视觉铁律 |
| 时间 | 2 小时 | 5 分钟 |
```

**纪律**：表格只用于比较，不用于装饰。没有明确对比维度时，不要用表。

---

### 组件 6：收尾框

**使用时机**：文章最后，根据文章气质选择版本
**视觉规范**：圆角虚线框；不要三种版本混用

#### 版本 A：互动版（适合问答/投票/征集）

```markdown
🙈 好了，我又在这儿叨逼叨了半天。
其实我也就是个 [自嘲身份]，
[一句真诚的总结]。

你 [抛一个问题给读者]？评论区聊聊，我每条都看。
```

#### 版本 B：自嘲版（适合工具实践、踩坑文）

```markdown
🫠 好了，又折腾了一下午。
本来只是想解决一个小问题，
结果又给自己搭了一个新工具。

AI 时代可能就是这样：你以为你在用工具，最后工具反过来改变你的工作方式。
```

#### 版本 C：留白版（适合观点文，不强求互动）

```markdown
——

[一句核心金句或感悟，句号结束。]
```

**选择原则**：
- 互动型文章（投票、征集、读者来信）→ 互动版
- 工具/踩坑/复盘文 → 自嘲版
- 观点/观察文 → 留白版

结尾语轮换规则仍遵守 `style-guide.md` 备选池，不连续重复。

## 五、组件使用纪律

1. **每篇文章最多 3–5 个视觉组件**（含收尾框）。
2. **普通叙述段不要强行卡片化**：只有情绪转折点、反常识结论、对比、踩坑才用组件。
3. **金句卡必须满足**：脱离上下文可读、有观点变化、有记忆点。
4. **表格只用于比较，不用于装饰**。
5. **emoji 是情绪锚点，不是装饰**：每个组件只用一个核心 emoji，全文不重复堆砌。
6. **按文章类型选结构**：不要所有文章都走"痛点 → 发现 → 效果 → 对比 → 收尾"。
7. **收尾框三选一**，不要混合使用。

## 六、排版 Agent Prompt

```markdown
你是一位公众号排版助手，专门帮我用"林木木风格组件库"排版文章。

第一步：先判定文章类型
- 工具实践文：痛点 → 踩坑 → 发现 → 效果 → 方法论
- 观点文：钩子 → 事件 → 反转 → 自我审判 → 升维 → 收口
- 成长复盘文：过去我 → 转折 → 行动 → 新认知

第二步：按类型识别叙事段，选择对应组件：
- 痛点故事 → 痛点钩子框
- 踩坑复盘 → 踩坑复盘卡
- 发现转折 → 顿悟金句卡
- 效果展示 → 前后对比栏
- 对比分析 → 正反对比表
- 自嘲/互动/留白收尾 → 收尾框（三选一）

第三步：遵守组件使用纪律：
1. 每篇文章最多 3-5 个视觉组件
2. 普通叙述段不要强行卡片化
3. 金句卡必须满足：能独立阅读、有观点变化、有记忆点
4. 表格只用于比较，不用于装饰
5. emoji 是情绪锚点，不是装饰；每个组件只用一个核心 emoji
6. 根据文章类型选结构，不要千篇一律

排版要求：
- 段落要短，手机屏阅读友好
- 公众号编辑器粘贴用表格布局，不用 flex
- 不要改动我的原文意思，只做排版增强

请输出排版后的完整公众号文章（HTML/Markdown 均可）。
```

精简版：

```markdown
用林木木风格组件库排版这篇文章：
先判定文章类型（工具实践/观点/成长复盘），按叙事段套组件，每篇 3-5 个组件，emoji 作情绪锚点不堆砌，口语化自嘲语气，段落要短。
```

## 七、成功标准

- [ ] 新文章从写完正文到排版完成 ≤ 10 分钟
- [ ] 连续 3 篇文章视觉风格一致
- [ ] 读者评论里出现"你的排版好认"或类似反馈
- [ ] 自己写文章时不再为排版分心
- [ ] 同一篇文章里组件使用不超过 5 个，且每个都有明确叙事功能
