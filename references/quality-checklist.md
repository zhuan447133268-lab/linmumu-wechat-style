# 林木木风格成稿自检清单

> 本清单用于 Agent 写完/排完版后做审计。逐条检查，不通过就改。也可以让用户自己抽检。

## 一、真实性

- [ ] 开头故事/案例来自真实事件，没有编造数据或对话
- [ ] 所有人名、地名、单位名已做泛化处理（除非用户明确要实名）
- [ ] 时间词按发布日重算，没有"昨天"过期的痕迹
- [ ] 技术细节/数字经过核对，没有拍脑袋写的"大概"

## 二、人设一致性

- [ ] 没有出现"AI小白""非技术背景"等禁用词
- [ ] 自嘲落在事（翻车、笨办法、口喷），不落身份
- [ ] 没有"我赢了""我太牛了"式自我宣布
- [ ] 没有上帝视角说教

## 三、语言风格

- [ ] 没有书面腔："该方法可以有效提升…""该工具具备以下特性…"
- [ ] 对话/引语是直接引语，没有缓冲转述
- [ ] 短句碎段，一句一段；长段不超过 4 行
- [ ] 业务术语已降维成大白话
- [ ] 没有 AI 腔排比和空泛金句

## 四、结构与升维

- [ ] 文章类型判定正确（工具实践/观点/成长复盘）
- [ ] 结构符合该类型的阶段划分
- [ ] 升维段有"不是X，而是Y"或类似对照结构
- [ ] 行动承诺小到可笑，不是口号
- [ ] 结尾语与上一篇不重复

## 五、组件与视觉

- [ ] 每篇文章视觉组件使用 3–5 个，没有强行卡片化
- [ ] 金句卡满足：脱离上下文可读、有观点变化、有记忆点
- [ ] 表格只用于比较，不用于装饰
- [ ] emoji 是情绪锚点，没有堆砌；同一 emoji 全文只出现一次
- [ ] 收尾框版本选择正确（互动/自嘲/留白三选一）
- [ ] 公众号编辑器粘贴用表格布局，不用 flex

## 六、读者收益

- [ ] 读者读完能回答："我得到了什么？"
- [ ] 观点或经验落在具体小动作，能直接照搬
- [ ] 标题-结尾闭环：标题立的 flag，结尾兑现了

## 使用方式

1. 成稿后把这份清单过一遍。
2. 任意一项不通过，回到对应环节修改。
3. 修改后重新自检，直到全部勾选。
4. 普遍性不通过项，追加到 `references/style-guide.md` 或 `references/examples.md`。
